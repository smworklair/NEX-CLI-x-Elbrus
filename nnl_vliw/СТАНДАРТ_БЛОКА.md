# 📐 NNL v1.0 Specification: Block Development Standard

This document specifies the rules for creating, training, and packaging neural network blocks for the **NNL (Neural Network Lego)** architecture.

Any block conforming to this specification plugs into the Motherboard on the fly without modifying Processor or Core code.

---

## 1. Block Directory Layout

Each block is packaged as a self-contained directory:

```
block_dir/
├── паспорт.json    # Block manifest and bus interaction rules
└── веса.npz        # Immutable archive of trained tensors/matrices
```

---

## 2. Block Manifest (`паспорт.json`)

The manifest must contain the following fields (exact JSON keys preserved for runtime compatibility):

```json
{
  "имя": "unique_block_name",
  "версия": 1,
  "роль": "description of the block's purpose",
  "архитектура": "architecture_module_name",
  "настройки": {
    "корзины": 65536,
    "размер": 48,
    "соль": "unique_block_salt"
  },
  "веса": {
    "файл": "веса.npz",
    "sha256": "sha256_checksum_of_weights_file",
    "чисел": 3152682
  },
  "пишет": [
    "concepts_the_block_may_write_to_bus"
  ],
  "читает": [
    "bus_concepts_subscribed_to_on_cycle_2"
  ],
  "ответы": [
    "complete_closed_list_of_block_answer_ids"
  ],
  "проекции": {
    "answer_1": {"bus_concept_A": 16.0, "bus_concept_B": 16.0}
  }
}
```

### Key Field Semantics
* **`архитектура`** — Python filename inside the architectures directory exporting the inference functions.
* **`читает`** — list of bus concepts the block needs for cycle-2 refinement. If any of these concepts appear on the bus, the Processor invokes the block on cycle 2.
* **`проекции`** — declarative mapping specifying which bus concepts a confirmed block answer projects onto. **The Core never guesses what an answer means — the block declares it explicitly.**
  For legacy blocks lacking `проекции`, the core does not decode them on its own: an application may pass an optional provider (`ЯдроПричинности(провайдер=...)`, method `проекция(block, answer_id) -> dict`), queried only when the passport is silent. Example for v8 blocks: `NNL/онтология_v8.py`. Without a provider, an answer with no declared projection writes nothing to the bus.
* **Namespaces.** A concept of the form `namespace:value` belongs to the namespace before the first `:`. The Core groups bus concepts by namespaces declared across `пишет`, `читает`, and `проекции` in passports (`матплата.пространства()`), remaining agnostic to their semantics. Concepts of the form `вывод_<block>:<answer>` are written automatically by the processor.

## 3. Block Architecture Software Contract

The architecture module (`архитектуры/<name>.py`) must export the following functions:

### 1. `загрузить(weights_path, passport) -> obj`
Loads weights from disk and returns an initialized in-memory model object.

### 2. `чисел(obj) -> int`
Returns the total parameter count (number of trained floats) in the model.

### 3. `проход2(obj, tokens, bus_slice) -> dict[answer_id, float]`
Runs inference over input tokens and the current bus slice.
* **Cycle 1:** `bus_slice == {}`. The block computes its local response in complete isolation.
* **Cycle 2:** `bus_slice` contains verified facts emitted by other blocks matching the `читает` field.

### 4. `синтез` or `экспорт(obj, tokens, bus_slice, top_answer) -> payload` *(optional)*
For generative or application blocks: builds a text response, structured card, or action command.

---

## 4. Isolation Contract (Lego Guarantee = 0.0000)

1. A block **must never** implicitly read global state or another block's internal state.
2. When invoked with an empty bus slice `{}`, the block's output must be strictly deterministic and independent of which other blocks occupy neighboring motherboard slots.

---

## 4a. The Bus: Signed Values, Sources, and Conflicts

* A bus concept value is a signed log-odds score: `+16.0` = "yes", `-16.0` = "no". Blocks declare negation the same way as affirmation: `"проекции": {"answer": {"fact": -16.0}}`.
* Multiple blocks may write the same concept. The Motherboard tracks values **per source** (by block name). If one source says "yes" (≥ `+1.0`) and another says "no" (≤ `-1.0`), that is a conflict: the concept is withheld from all bus slices (readers see "nobody wrote it"), and a conflict record is returned in the processor result (`конфликты`). Outcome depends on disagreement, never on block execution order.
* Agreeing sources do not sum: the concept value is the largest by magnitude. Ten agreeing blocks do not make a fact ten times stronger.
* Implication for block authors: never write a concept to the bus unless you have your own direct evidence; "confirming" another block's concept is disallowed (checked by insertion linting below).

## 5. Pre-Deployment Verification (NNL Linter)

Before plugging a block into a live system, run the linter:

```bash
python NNL/линтер.py <path_to_block_dir>
```

The linter automatically verifies:
* Structural validity of `паспорт.json`.
* SHA-256 match of the weights file.
* Presence and signatures of required architecture functions.
* A dry-run forward pass in isolated mode.

The linter also verifies **insertion** into a running system (`python NNL/линтер.py <block_dir> --вставка <neighbor_dir> ...`):
* neighbor answers on control prompts shift by at most ε (default 1%; the real commands block shifts 0%, prior v8 measurement was 0.22%);
* on cycle 1, neighbor answers do not change on any prompt (Lego index 0);
* on cycle 1, the new block's output matches its standalone output;
* removing the block restores neighbor answers to their exact prior values.
