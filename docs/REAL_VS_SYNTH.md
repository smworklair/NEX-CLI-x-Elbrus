# Настоящий код против синтетики

> Этап 11 из 13 · [← Модель машины](ISA.md) · [Маршрут](README.md) · [Обученная LLM →](LEARNED.md)

Граница, без которой числа проекта читаются неверно: настоящий вывод `lcc` и обучающая синтетика —
разные распределения. Проверка воспроизводится локально:

```bash
python3 tools/check_real_vs_synth.py
```

## Откуда числа

Кросс-`lcc` 1.29.16 компилирует пять обычных C-программ (накопление, плавающая точка, ветвление,
копирование памяти, хеш строки) на `-O0/-O2/-O3`. Результат разбирается тем же парсером, что и весь проект.

Тот же цикл, скомпилированный настоящим `lcc` на машине e2k по SSH, дал 49 операций против 50 —
кросс-компилятор репрезентативен, доступ к железу для этого вопроса не нужен.

## Главное: словари не пересекаются

Обучающая выборка — восемь целочисленных классов: `ADD`, `MUL`, `LOAD`, `SUB`, `AND`, `SHL`, `DIV`, `STORE`.

В настоящем выводе компилятора:

- **37% операций получают класс `UNKNOWN`** — мнемоник нет в словаре.
- Это не экзотика: предикаты (`cmpesb`, `landp`), упакованный SIMD (`qpaddw`), AAU (`aaurw`, `fapb`),
  вся плавающая точка (`faddd`, `fmuld`). На программе с `double` незнакомых **100%**.
- Обратно: `DIV` занимает 3–7% синтетики, а в настоящем выводе не встретился ни разу.
- Размеры: синтетика 4–24 операции, однострочный `memcpy` на `-O3` — 112.

## Оговорка

`UNKNOWN` — заглушка: латентность 1, любой канал. Расписание по ней физике не соответствует:
`fdivd` не исполняется за такт. Смысл класса в том, что это **видно в каждом отчёте**, а не спрятано
под `ADD`.

Верными числа станут только после пополнения `MNEMONICS` настоящими классами с замером портов.
Пока этого нет, вывод про настоящий код читается так: **«структура графа — примерно, времена — нет»**.

## Что из этого следует

1. **Сузить заявку** до целочисленного ALU-подмножества e2k — тогда текущие данные валидны.
2. **Расширить словарь** — предикаты, SIMD, AAU, плавающая точка. Это недели замеров, не часы.
3. **Учить на выводе `lcc`** вместо синтетики. Но тогда эталон — решение компилятора, а не доказанный оптимум.

Это развилка приоритетов, а не техническая зависимость: обучающие данные генерирует `tools/vliw_gen.py`
через CP-SAT, парсер ассемблера он не импортирует.

жадный уже оптимален в 94% блоков. Подробные цифры — [`TINY.md`](TINY.md).
