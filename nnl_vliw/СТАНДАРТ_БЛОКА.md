# 📐 Спецификация NNL v1.0: Стандарт разработки блока

Этот документ описывает правила создания, обучения и упаковки нейросетевых блоков для архитектуры **NNL (Neural Network Lego)**.

Любой блок, соответствующий этой спецификации, подключается к Матплате на лету без изменения кода Процессора или Ядра.

---

## 1. Структура папки блока

Каждый блок оформляется как отдельная изолированная директория:

```
папка_блока/
├── паспорт.json    # Манифест блока и правила взаимодействия с шиной
└── веса.npz        # Неизменяемый архив с обученными тензорами/матрицами
```

---

## 2. Манифест блока (`паспорт.json`)

Манифест обязан содержать следующие поля:

```json
{
  "имя": "уникальное_имя_блока",
  "версия": 1,
  "роль": "описание назначения блока",
  "архитектура": "имя_модуля_архитектуры",
  "настройки": {
    "корзины": 65536,
    "размер": 48,
    "соль": "уникальная_соль_блока"
  },
  "веса": {
    "файл": "веса.npz",
    "sha256": "контрольная_сумма_sha256_файла_весов",
    "чисел": 3152682
  },
  "пишет": [
    "понятия_которые_блок_может_писать_на_шину"
  ],
  "читает": [
    "понятия_шины_на_которые_блок_подписан_на_такте_2"
  ],
  "ответы": [
    "полный_закрытый_список_идентификаторов_ответов_блока"
  ],
  "проекции": {
    "ответ_1": {"понятие_шины_А": 16.0, "понятие_шины_Б": 16.0}
  }
}
```

### Назначение ключевых полей:
* **`архитектура`** — имя Python-файла в папке архитектур, содержащего функции инференса.
* **`читает`** — список понятий шины, которые нужны блоку для уточнения на Такте 2. Если на шине появляется любое из этих понятий, Процессор запускает блок на Такте 2.
* **`проекции`** — декларативное правило: в какие понятия шины проецируется подтверждённый ответ блока. **Ядро не угадывает смысл ответа — блок сам его объявляет.**
  Блоки старого формата без `проекции` ядро не расшифровывает: приложение может передать необязательный провайдер
  (`ЯдроПричинности(провайдер=...)`, метод `проекция(блок, ответ_id) -> dict`), который спрашивают только когда паспорт молчит.
  Пример для блоков v8 — `NNL/онтология_v8.py`. Без провайдера ответ без объявленной проекции ничего не пишет на шину.
* **Пространства имён.** Понятие вида `пространство:значение` относится к пространству до первого «:». Ядро группирует понятия на шине по пространствам,
  объявленным в `пишет`, `читает` и `проекции` паспортов (`матплата.пространства()`), и не знает, что они значат. Понятия `вывод_<блок>:<ответ>` пишет сам процессор.

---

## 3. Программный контракт архитектуры блока

Код архитектуры (`архитектуры/<имя>.py`) обязан экспортировать следующие функции:

### 1. `загрузить(путь_к_весам, паспорт) -> obj`
Загружает веса из файла на диске и возвращает инициализированный объект модели в памяти.

### 2. `чисел(obj) -> int`
Возвращает суммарное количество параметров (обученных чисел) в модели.

### 3. `проход2(obj, токены, срез_шины) -> dict[ответ_id, float]`
Выполняет инференс по входным токенам и текущему срезу шины.
* **На Такте 1:** `срез_шины == {}`. Блок считает локальный отклик в полной изоляции.
* **На Такте 2:** `срез_шины` содержит проверенные факты от других блоков, объявленные в поле `читает`.

### 4. `синтез` или `экспорт(obj, токены, срез_шины, top_ответ) -> payload` *(опционально)*
Для генеративных или прикладных блоков: формирует текстовый ответ, структурированную карточку или команду действия.

---

## 4. Контракт изоляции (Гарантия Lego = 0.0000)

1. Блок **не имеет права** неявно использовать глобальные переменные или состояние других блоков.
2. При вызове с пустым срезом шины `{}` результат блока должен быть строго детерминирован и не зависеть от того, какие блоки подключены в соседние слоты матплаты.

---

## 4а. Шина: значения со знаком, источники и конфликты

* Значение понятия на шине — оценка в логарифме шансов со знаком: `+16,0` — «да», `−16,0` — «нет». Блок объявляет отрицание так же, как утверждение:
  `"проекции": {"ответ": {"факт": -16.0}}`.
* Понятие может писать несколько блоков. Матплата хранит значения **по источникам** (по имени блока). Если один источник говорит «да» (≥ +1,0), а другой «нет»
  (≤ −1,0), это конфликт: понятие не попадает ни в один срез (читающий блок получает «никто не написал»), запись о конфликте возвращается в результате
  процессора (`конфликты`). Решает не порядок блоков, а несовпадение мнений.
* Согласные источники не складываются: значение понятия — наибольшее по модулю. Согласие десятка блоков не делает понятие в десять раз сильнее.
* Следствие для автора блока: не пишите на шину понятие, о котором у вас нет собственной оценки; чужие понятия «подтверждать» нельзя (см. проверку вставки ниже).

## 5. Проверка блока перед подключением (NNL Linter)

Перед подключением блока в боевую систему запустите линтер:

```bash
python NNL/линтер.py <путь_к_папке_блока>
```

Линтер автоматически проверит:
* Корректность структуры `паспорт.json`.
* Совпадение sha256 файла весов.
* Наличие и сигнатуры методов архитектуры.
* Пробный проход в изолированном режиме.


Линтер дополнительно проверяет **вставку** блока в работающую систему (`python NNL/линтер.py <папка_блока> --вставка <папка_соседа> ...`):
* ответы соседей на контрольных вопросах меняются не более чем на ε (по умолчанию 1 %; настоящий блок «команды» меняет 0 %, прежний замер v8 — 0,22 %);
* на такте 1 ответы соседей не меняются ни на одном вопросе (Lego-индекс 0);
* ответ нового блока на такте 1 равен его соло-ответу;
* после снятия блока ответы соседей возвращаются к прежним.
