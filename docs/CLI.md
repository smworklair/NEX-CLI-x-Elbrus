быстрый режим отличается от интерактивного, что делает каждая команда, как
работают Tab-дополнение и история ввода, и что делать, если что-то не
запускается.

о том, *что вообще измеряет* этот прототип и почему, — в

## Установка и требования

**Требуется Python 3.10 или новее.** Проверить свою версию:

```bash
python3 --version
```

**Устанавливать нечего.** У проекта нет обязательных зависимостей — только
стандартная библиотека Python. Нет ни `requirements.txt`, ни `pyproject.toml`,
ни `setup.py`, и они не нужны: `pip install` для запуска не требуется вообще.

Опциональных зависимостей две, обе можно пропустить:

```bash
python3 -m venv .venv
.venv/bin/pip install textual   # три полноэкранных режима
.venv/bin/pip install rich      # панели вокруг заметных блоков отчётов
.venv/bin/python -m vliw
```

[`textual`](https://github.com/Textualize/textual) даёт полноэкранный
интерфейс: верстак интерпретатора, интерактивную решётку расписания и диалог
с трассой. Без него запускается прежний однооконный экран на `curses` из
стандартной библиотеки, а если недоступен и он — построчный режим.
[`rich`](https://github.com/Textualize/rich) украшает панели отчётов; без
него те же блоки рисуются рамками из ANSI.

Если в системе нет `pip` (в некоторых сборках Ubuntu он вынесен в отдельный
пакет и `python3 -m venv` из-за этого не создаёт его в окружении), venv можно
собрать без него и доставить pip отдельно:

```bash
python3 -m venv --without-pip .venv
curl -sS https://bootstrap.pypa.io/get-pip.py | .venv/bin/python
.venv/bin/pip install textual
```

**Как получить сам код.** Это обычная папка с исходниками Python, без сборки
и без публикации в PyPI. Если она у вас уже есть (например, как сейчас) —
просто перейдите в неё, никаких дополнительных шагов не нужно. Если получаете
её впервые — склонируйте репозиторий (`git clone …`) или скопируйте папку
`vliw-ai-scheduler-demo` целиком тем способом, которым вам её передали; после
этого содержимое сразу готово к запуску.

**Проверка, что всё на месте:**

```bash
cd vliw-ai-scheduler-demo
python3 -m vliw --help
```

Если увидели список флагов и команд — всё установлено верно, дальше можно
переходить к быстрому старту.

## Быстрый старт

Две вещи ломают запуск чаще всего — обе не про сам инструмент, а про то, как
его вызвать.

**1. Команду нужно запускать из папки проекта.** `python -m vliw` ищет пакет
`vliw` в текущей рабочей директории. Если вы стоите в `~`, а проект лежит в
`~/vliw-ai-scheduler-demo`, Python скажет `No module named vliw` — он прав,
пакета там действительно нет. Сначала зайдите в папку:

```bash
cd ~/vliw-ai-scheduler-demo
```

**2. Команда называется `python3`, не `python`.** На многих системах (в том
числе в этом окружении) просто `python` не существует — только `python3`. Все
примеры в этом файле используют `python3`; если у вас `python` тоже указывает
на Python 3.10+, можно и его.

После этого:

```bash
cd ~/vliw-ai-scheduler-demo
python3 -m vliw
```

Один клиент, один промпт `nex`. Слэш не обязателен.

```
sum 8
compare
doctor
почему этот участок медленный?
```

Ядра: `sum`, `dot`, `saxpy`, `chase`, `div`, `gemm`, `horner`, `fir`, `rms`,
`copy`, `addn`. Своя запись: `a=load; b=load; t=a*b; store t`. Список: `work`.

**Если забыли, что тут вообще есть.** Стандартный флаг `-h`/`--help`
работает всегда, до захода в интерактив — печатает все глобальные флаги и
список всех команд прямо в терминале, без запуска цикла:

```bash
python3 -m vliw --help
python3 -m vliw -h        # то же самое, короткая форма
```

Это самый быстрый способ вспомнить набор команд, если под рукой нет этого
файла.

## Два режима: разово или в цикле

Это **один и тот же набор команд**, вызванных двумя способами. Никакой разницы
в возможностях между ними нет — только в том, возвращаетесь вы в терминал
после каждой команды или остаётесь в программе.

### Быстрый (разовый) режим — для скриптов и одиночных вызовов

```bash
python3 -m vliw <команда> [аргументы]
```

Команда пишется **без** ведущего `/`. Программа выполняет её и завершается —
удобно вызывать из shell-скриптов, из `Makefile`, из CI, или просто когда
нужен один быстрый ответ, не заходя в цикл:

```bash
python3 -m vliw sum 8
python3 -m vliw run slotclash
python3 -m vliw compare --no-color
python3 -m vliw all
```

### Интерактивный режим — для исследования

```bash
python3 -m vliw
```

Без аргументов открывается **экран выбора режима**. Режимов три, и это три
отдельных рабочих места со своей раскладкой:

| режим | что на экране | для чего |
|---|---|---|
| **1 ЯДРО** | лента вычислений; панели ИМЕНА, ПАМЯТЬ, ПРОГРАММА | посчитать что-то своё и собрать из этого граф участка |
| **2 РАЗБОР** | решётка «такты × каналы», ПОЧЕМУ ЗДЕСЬ, ЧИСЛА, ДИАГНОЗ, МАШИНА | понять, где теряются такты и почему |
| **3 АГЕНТ** | диалог; ЧТО ВИДИТ АГЕНТ, ТРАССА | спросить обычным языком и проверить ответ |

**Цифры работают клавишами только на экране выбора.** Внутри режима вся
клавиатура принадлежит строке ввода: `2+2` в интерпретаторе должно начинаться
с двойки, а не с переключения экрана. Вернуться к выбору — `/clear` или `^O`.

**Палитра команд** — наберите «/», и над полем ввода всплывает список.
Выбранный пункт подсвечен, `↑↓` листают, `Tab` подставляет, `Enter` запускает,
`Esc` закрывает:

```
  /run                <сценарий>      прогнать сценарий: расписание + вердикт
  /compare            [сценарий]      baseline и oracle бок о бок
  /play               [base|oracle]   воспроизвести расписание такт за тактом
  /asm                [base|oracle]   расписание как широкие команды e2k { … }
  nex ▸ /
```

**Решётка расписания** (РАЗБОР) — строка это такт, столбец канал, в клетке
операция цветом своего типа. Метка такта показывает загрузку широкой команды:
`█` полная пачка, `▄` частичная, `▁` такт без выдачи. `▸` помечает операции,
которые оракул ставит иначе, чем baseline. `Esc` отдаёт клавиатуру решётке,
стрелки водят курсор, панель **ПОЧЕМУ ЗДЕСЬ** отвечает про клетку под ним —
включая пустую: чего ждём, кто держит канал, какая операция была готова.
`Enter` на клетке запускает `/explain` для этого такта.

Долгий счёт (точный поиск) идёт в отдельном потоке — экран не замирает, в
правом углу строки ввода видно «считаю…».

Клавиши в полноэкранном режиме:

| клавиша | действие |
|---|---|
| `1` `2` `3` | выбрать режим — **только на экране выбора**; внутри режима это обычный ввод |
| `/` | открыть палитру команд над полем ввода |
| `Enter` | выполнить (при открытой палитре — выбранное в ней; в решётке — разбор такта) |
| `Tab` | подставить выбранное в палитре / дополнить аргумент |
| `↑` / `↓` | выбор в палитре, а когда она закрыта — история команд |
| `Esc` | закрыть палитру; при закрытой — переложить фокус между вводом и решёткой |
| **мышь** | прокрутка, клик по чипам (ядра, участки, вопросы), выбор клетки в решётке |
| `^B` | убрать/вернуть боковую колонку — рабочая область разворачивается на всю ширину |
| `^T` | убрать/вернуть полосу подсказок (ядра, участки, вопросы) |
| `^O` | к выбору режима (то же, что `/clear`) |
| `^Q` | выход (то же, что `/exit`) |

**Про цвет.** Интерфейс рассчитан на 24-битный цвет: поверхности (полотно,
панель, активная панель) различаются тонко, и в палитре из 256 цветов
сливаются в один чёрный. WSL и большинство дистрибутивов выставляют
`TERM=xterm-256color` и **не** выставляют `COLORTERM`, поэтому библиотека
вывода считает, что цветов 256. Инструмент сам подставляет
`COLORTERM=truecolor`, если терминал на это похож (`*-256color`, kitty,
alacritty, wezterm, ghostty, foot, Windows Terminal), и не трогает переменную,
если она уже задана или если `TERM` — консоль без цвета (`linux`, `dumb`).
Принудительно задать своё значение можно снаружи:

```bash
COLORTERM=truecolor .venv/bin/python -m vliw   # заставить 24-битный цвет
COLORTERM= .venv/bin/python -m vliw            # оставить 256 цветов
```

**Когда полноэкранный режим не включается** (и это нормально): если вывод не
в терминал (пайп, перенаправление), если не установлен ни `textual`, ни
`curses`, или если явно передан `--plain`/`--no-color`. Тогда
работает обычный построчный цикл — те же команды, тот же вид отчётов, просто
без панели:

1. печатается логотип;
2. сразу прогоняется сценарий `slotclash` — чтобы был вывод, а не пустой экран;
3. дальше цикл: приглашение `vliw ▸`, строка, результат, снова приглашение —
   пока не наберёте `/exit`.

```bash
python3 -m vliw --plain     # принудительно обычный построчный режим
```

Внутри цикла команды пишутся **с** ведущим `/`: `/run slotclash`, `/compare`,
`/model naive`. Одна строка — одна команда — один Enter; никакого «живого»
всплывающего меню нет и не будет (см. [ниже](#почему-не-live-палитра)) — но
есть Tab-дополнение и история, которые решают ту же задачу «не печатать всё
руками» надёжнее.

Можно смешать: передать флаги моделирования снаружи, а работать внутри цикла:

```bash
python3 -m vliw --profile naive_homogeneous
```

## Коды возврата (для скриптов и CI)

Разовый режим предназначен именно для скриптов — значит, ему нужен честный
код возврата, а не только текст в stdout. Вот полный контракт:

| код | когда |
|---|---|
| `0` | команда выполнена успешно |
| `1` | ошибка: неизвестная команда, неизвестный сценарий или профиль, битые аргументы, внутренняя проверка расписания провалилась |
| `130` | прервано по Ctrl+C |

```bash
python3 -m vliw run slotclash
if [ $? -ne 0 ]; then
    echo "что-то пошло не так" >&2
    exit 1
fi
```

или короче:

```bash
python3 -m vliw run slotclash && echo "успех" || echo "провал"
```

Опечатанная команда тоже возвращает `1`, а не тихо завершается с `0` —
проверено:

```bash
$ python3 -m vliw frobnicate; echo "код: $?"
неизвестная команда /frobnicate.  Может, вы имели в виду: /probe?
код: 1
```

## Глобальные флаги

Действуют что в быстром режиме, что при запуске интерактивного цикла (задают
стартовые настройки сессии, дальше `--profile`/`--width` можно поменять
командой `/model` прямо в цикле).

**Расположение не важно** — флаг можно поставить и до имени команды, и после,
результат одинаковый:

```bash
python3 -m vliw --profile naive_homogeneous run slotclash
python3 -m vliw run slotclash --profile naive_homogeneous   # то же самое
```

Единственное жёсткое правило — значение флага должно идти сразу за ним
(`--profile naive_homogeneous`, не раздельно через другие токены).

| флаг | что делает | по умолчанию |
|---|---|---|
| `-h`, `--help` | список флагов и команд, сразу выход | — |
| `--version` | показать версию и выйти |
| `--profile {e2k-v6-measured,e2k-v6-firstprobe,naive_homogeneous}` | какая модель машины: проверенная ассемблером, опровергнутая первая версия (для сравнения) или вырожденная наивная | профиль сценария, обычно `e2k-v6-measured` |
| `--width N` | переопределить число портов широкой команды | ширина профиля (обычно 6) |
| `--budget SEC` | бюджет на точный поиск оракула, секунд | `10` |
| `--portfolio SEC` | бюджет запасного (портфельного) поиска, если точный не уложился | `3` |
| `--theme ИМЯ` | тема оформления (`nex-dark`, `kilo`, `classic`) | `nex-dark` |
| `--plain` | не включать полноэкранный режим, работать построчно | выключен |
| `--color` / `--no-color` | принудительно включить/выключить цвет | автоопределение по терминалу |

```bash
python3 -m vliw --width 3 all
python3 -m vliw --no-color selfcheck   # для вывода в файл/лог без ANSI-кодов
```

`--no-color` полезен, когда вывод идёт не в терминал (например,
`python3 -m vliw run slotclash > report.txt`) — программа и сама определяет
это автоматически, но флаг форсирует поведение явно.

**Что видно, когда точного поиска не хватило (`--budget`/`--portfolio`).**
Оракул сначала пытается доказать оптимум точным поиском в пределах `--budget`
секунд; не успел — переключается на запасной (портфельный) поиск в пределах
`--portfolio` секунд и берёт лучшее найденное, БЕЗ доказательства, что лучше
уже некуда. Разница видна прямо в панели вердикта — сравните:

```
║ оптимум оракула доказан точным поиском ║        ← бюджета хватило

║ оптимальность НЕ доказана (лучшее найденное)  ║  ← не хватило, взяли что нашли
```

Реальный пример (сценарий `wide_ilp` — 63 инструкции, точному поиску за
типовой бюджет не хватает времени даже по умолчанию):

```bash
$ python3 -m vliw --no-color run wide_ilp
╔═ ВЕРДИКТ ═════════════════════════════════════╗
║ РАЗНИЦЫ НЕТ — жадная эвристика уже оптимальна ║
║                                               ║
║ baseline (эвристика)     :  117 тактов        ║
║ oracle (точный поиск)    :  117 тактов        ║
║ нижняя граница (предел)  :  112 тактов        ║
║                                               ║
║ оптимальность НЕ доказана (лучшее найденное)  ║
╚═══════════════════════════════════════════════╝
```

Здесь baseline и oracle совпали (117), но раз оптимальность не доказана —
это может быть как «эвристика и правда уже оптимальна», так и «портфельный
поиск не нашёл ничего лучше за отведённое время»; отличить одно от другого
можно только увеличив `--budget`/`--portfolio` и повторив.

## Все команды

Каждая работает одинаково что снаружи (`python3 -m vliw run slotclash`), что
внутри цикла (`/run slotclash`). Ниже — с `/`, как в интерактиве.

### Исследовать сценарий

| команда | что делает |
|---|---|
| `/run <сценарий>` | прогнать сценарий: расписание оракула (пачки-рамки), статистика, вердикт |
| `/compare [сценарий]` | baseline и oracle **бок о бок**, с подсветкой первого расхождения |
| `/play [base\|oracle]` | воспроизвести расписание такт за тактом (Enter — следующий такт, `q` — прервать) |
| `/asm [base\|oracle]` | то же расписание, но в виде реальных широких команд e2k: `{ … }`, каналы `,0`…`,5`, мнемоники (`sdivs`, `muls`), `nop` на простоях |
| `/explain <такт>` | почему именно в этот такт baseline и oracle выбрали то, что выбрали |
| `/path` | граф зависимостей с подсветкой критического пути (★) |
| `/bounds` | две нижние границы makespan (по критическому пути и по пропускной способности) и какая из них связывает |

`/run` без аргумента использует текущий сценарий сессии (по умолчанию
`slotclash`); `/run <ключ>` переключает сценарий и дальше он «текущий» и для
`/compare`, `/path`, `/bounds` и т.д. без повторного указания.

### Работа с настоящим кодом и диагностика

Это то, ради чего инструмент существует: не смотреть на готовые примеры, а
разбирать **ваш** код и говорить, где он теряет такты.

| команда | что делает |
|---|---|
| `/load <файл.s>` | разобрать настоящий `.s`-вывод lcc: широкие команды `{ }`, каналы `,0`…`,5`, `nop N` → граф зависимостей. Показывает расписание самого компилятора, результат точного поиска и **резерв** между ними |
| `/doctor [base\|oracle]` | пройти по расписанию правилами-детекторами и выдать список проблем с ценой в тактах, причиной и что менять |

Попробовать прямо сейчас — в репозитории лежит образец:

```bash
python3 -m vliw load examples/probe.s
```

```
  ФАЙЛ: examples/probe.s
  24 операций  ·  15 широких команд  ·  45 тактов в nop

  расписание компилятора (lcc)     60 т.
  точный поиск (oracle)            59 т.
  теоретический предел             52 т.

  РЕЗЕРВ: 1 т. из 60 (2%) — столько отыгрывает точный поиск на том же графе.
```

**`/doctor` — самое важное.** Он различает две принципиально разные вещи, и
это видно в выводе двумя отдельными разделами:

- **МОЖНО ОТЫГРАТЬ** — такты, потерянные из-за порядка выдачи. Признак
  строгий: монопольный порт занят операцией, которая **менее** срочна
  (её остаточный критический путь короче), чем та, что из-за неё стоит.
- **ПРЕДЕЛЫ МАШИНЫ** — ждать было правильно: порт занят более срочной
  работой, или готовой работы просто нет. Это не ошибка планировщика.

```
  МОЖНО ОТЫГРАТЬ (2)
  !!    −12 т.  монопольный порт ,5 занят менее срочной z0
        где: dc готова в т.1, выдана только в т.13
        почему: порт ,5 — единственный исполнитель DIV; его 12 т. занимала z0
        (DIV, остаток пути 17), пока ждала dc (остаток 27) — более срочная
        что делать: выдать dc раньше z0: z0 никто не ждёт, её можно посчитать
        позже, в тени длинной операции
```

Диагностика **детерминированная**: никакой языковой модели и никакой сети,
только правила по расписанию. Поэтому вывод воспроизводим и проверяем руками
по решётке. На доказанно оптимальных расписаниях раздел «можно отыграть»
пустой — инструмент не выдумывает проблемы там, где их нет.

Верхние находки видны и в боковой панели полноэкранного режима, в разделе
«ДИАГНОЗ BASELINE».

### Модель машины

| команда | что делает |
|---|---|
| `/model` | показать матрицу возможностей портов и латентности текущего профиля |
| `/model <профиль>` | переключить профиль: `e2k-v6-measured` (проверенный) ↔ `e2k-v6-firstprobe` (опровергнутая первая версия) ↔ `naive` (`naive_homogeneous`) |
| `/probe` | как снята модель: матрица портов — у ассемблера, латентности — цепочками зависимых; и в чём была ошибка первой версии |

### Массовые прогоны и графы

| команда | что делает |
|---|---|
| `/scenarios` | список встроенных сценариев по группам: работа планировщика и приёмы оптимизации (форма графа, цена операции, циклы, память, ветвления) — с одной строкой «чему учит» у каждого |
| `/random [N] [seed]` | сгенерировать случайный граф на `N` инструкций (по умолчанию 16) и сразу прогнать |
| `/all` | сводная таблица: baseline / oracle / выигрыш по всем встроенным сценариям |
| `/sweep [--seeds N] [--sizes A,B,C] [--widths X,Y,Z] [--time-limit SEC]` | массовый прогон по случайным графам на разных конфигурациях машины — статистика, как часто и насколько эвристика проигрывает |
| `/selfcheck [--seeds N] [--time-limit SEC]` | независимая проверка: сверить оптимум оракула с грубым полным перебором |

Опции `sweep`/`selfcheck` пишутся как `--ключ значение`, например:

```
/sweep --seeds 15 --sizes 10,14 --time-limit 60
/selfcheck --seeds 30
```

Что реально видно на выходе — коротко, по одному примеру на команду.

`/random 10 42` (10 инструкций, seed 42 — тот же seed всегда даёт тот же
граф) генерирует граф и сразу прогоняет его как `/run`:

```
сгенерирован случайный граф: 10 инструкций, seed=42
[дальше — обычный вывод /run: расписание, вердикт]
```

`/sweep --seeds 2 --sizes 8 --widths 6 --time-limit 15` — таблица по
конфигурациям машины: сколько случайных графов дали разрыв между эвристикой
и оракулом, и насколько. На двух случайных графах разрыв может и не
встретиться — это тоже честный результат, не «пустой» и не ошибка:

```
МАССОВЫЙ ПРОГОН ПО СЛУЧАЙНЫМ ГРАФАМ
────────────────────────────────────────────────────────────────
  2 случайных графов × размеры [8] × конфигурации машины. …

  модель              кан.  слоты          с разрывом  доля  средний разрыв  …
  ──────────────────  ────  ─────────────  ──────────  ────  ──────────────
  e2k-v6-measured        6  неравноправны        0/2    0%               —
  naive_homogeneous      6  равноправны           0/2    0%               —
```

На большей выборке разрыв виден отчётливее — например, `--seeds 25` уже
находит его в нескольких графах из 75 (полная таблица и разбор — в
[README](../README.md#результаты)).

`/selfcheck --seeds 3 --time-limit 15` — сверяет оптимум оракула с грубым
полным перебором на маленьких графах и печатает вердикт одной строкой (плюс
список расхождений, если найдутся — в исправном проекте их быть не должно):

```
Сверяем оракул (точный поиск) с независимым полным перебором: 3 графов × 4
размеров × 4 моделей.
Полный перебор считается только на маленьких графах — это нормально.

OK: 48 проверок, расхождений нет (4 с).
  Оптимальность, которую заявляет оракул, подтверждена независимым перебором.
```

### Справка и объяснения

| команда | что делает |
|---|---|
| `/status` | контекст сессии: сценарий, машина, результат, состав графа (то же, что в боковой панели) |
| `/theme [имя]` | список тем оформления; с именем — переключить |
| `/docs` | что вообще показывает этот прототип и зачем — для тех, кто зашёл впервые |
| `/agent` | куда в проекте встраивается будущая обученная модель (`vliw/learned/`) |
| `/help` (или пустая строка, или голое `/`) | список всех команд текстом |
| `/clear` (или `/cls`) | очистить экран и вернуться к выбору приложения (ИССЛЕДОВАНИЕ / NEX AGENT) |
| `/exit` (или `exit`, `/quit`, `quit`, Ctrl+D) | выйти |

### Темы оформления

Палитра вынесена в JSON — `vliw/ui/themes/*.json`, по файлу на тему. Менять
цвета можно, не трогая код:

```bash
python3 -m vliw --theme classic run slotclash   # снаружи
```
```
vliw ▸ /theme classic                           # или прямо в сессии
```

- **`nex-dark`** (по умолчанию) — чёрный фон, синий основной акцент, амбра
  вторичным. Рассчитана на терминал с 256 цветами.
- **`classic`** — та же схема на базовых 8 цветах, для терминалов без
  поддержки 256 цветов.

Внутри файла темы два раздела. `roles` — оформление интерфейса (акцент,
рамки, приглашение, заголовки, панель). `ops` — **цвета операций**, и это
намеренно отдельный раздел: они не украшение, а данные. Именно по разным
цветам `MUL` и `DIV` видно, что умножитель и делитель сидят каждый на своём
единственном порту `,5`, — то есть главная мысль всего демо. Тема может их
перекрашивать, но обязана оставлять различимыми.

Своя тема — это копия файла с изменёнными номерами цветов (индексы
256-цветной палитры терминала); она сразу появится в `/theme`. Битый или
отсутствующий JSON инструмент не роняет — подставляется встроенная запасная
палитра.

### Как программа понимает сокращённое имя команды

Работают два независимых механизма, и у них есть чёткий порядок проверки —
по очереди, до первого совпадения:

1. **Явные алиасы** — фиксированный список, проверяется первым и всегда
   побеждает: `/r` → `/run`, `/cmp` → `/compare`, `/ls` → `/scenarios`,
   `/cls` → `/clear`.
2. **Однозначное сокращение имени** — если введённый текст является началом
   ровно одного имени команды, программа достраивает его сама: `/comp`
   разрешится в `/compare`, потому что это единственная команда, начинающаяся
   на «comp». Если начал совпадает несколько команд — сокращение НЕ
   разрешается (нужно уточнить, например через Tab).

Явный алиас существует именно там, где короткая форма сама по себе
неоднозначна: `/r` — это начало сразу двух команд, `run` и `random`, поэтому
как «однозначное сокращение» оно бы не сработало (`/r` без алиаса выдал бы
ошибку из-за неоднозначности) — но так как `/r` явно прописан как алиас
`/run`, он срабатывает безусловно, до всякой проверки на неоднозначность.
Короче: **алиас побеждает всегда, сокращение — только если оно и правда
единственное**.

## Интерактивный режим: что умеет ввод

### Tab-дополнение

Нажатие **Tab** дополняет:
- имя команды на первом слове: `/co<Tab>` → `/compare` (если совпадение
  однозначно; при нескольких — ничего не подставит, наберите ещё символ);
- аргумент на втором слове, по контексту команды: после `/run `, `/compare `
  дополняются имена сценариев; после `/model ` — имена профилей; после
  `/play `, `/asm ` — `baseline`/`oracle`.

### История ввода (стрелки ↑ / ↓)

Стрелка **вверх** пролистывает раньше введённые команды, **вниз** — обратно.
История сохраняется между запусками в файле `~/.vliw_history` (до 1000
последних команд) — то, что вы набирали вчера, доступно по стрелке вверх и
сегодня.

Обе эти возможности идут от стандартного модуля Python `readline`. Если он
недоступен в вашей сборке Python (изредка бывает на Windows без
дополнительных пакетов) — программа тихо работает без Tab и истории, просто
обычным построчным вводом; ничего не ломается.

#### Почему не live-палитра

В более ранней версии на голый `/` всплывал самостоятельно нарисованный
список команд с выбором стрелками — красиво, но хрупко: собственный код
управления терминалом (сырой режим, ручная перерисовка) ломался на разных
размерах терминала и при вставке текста. От него отказались в пользу
`readline` — той же библиотеки, что даёт историю и дополнение в `bash` и
`python3` REPL: она десятилетиями обкатана именно на этих задачах и не
рассыпается там, где ломался самодельный код.

### Вставка текста (paste) безопасна

Если в буфере обмена был кусок кода и вы случайно вставили его вместо
команды — каждая строка воспринимается как отдельная попытка команды, но
сообщение об ошибке печатается **один раз**, а не по разу на строку:
остальные «нечто, начинающееся не с `/`» молча считаются и в конце выводится
`(проигнорировано ещё N строк — не команды)`.

### Прерывания: Ctrl+C и Ctrl+D

- **Ctrl+C на пустом приглашении** — отменяет текущую строку ввода (`^C`),
  сессия продолжается.
- **Ctrl+C во время выполнения команды** (например, долгий `/sweep`) —
  прерывает именно эту команду (`^C команда прервана`), возвращает к
  приглашению; ничего не падает и не сыплет трейсбеком.
- **Ctrl+C в разовом вызове** (`python3 -m vliw all`, не в цикле) — программа
  завершается сразу, аккуратно, без трейсбека (код возврата 130).
- **Ctrl+D** (конец ввода) или закрытый пайп — обычный выход, как `/exit`.

## Проблемы и решения

**`No module named vliw`**
Вы не в папке проекта. `cd ~/vliw-ai-scheduler-demo`, затем повторите
команду.

**`python: command not found`**
На вашей системе интерпретатор называется `python3`. Используйте
`python3 -m vliw …` вместо `python -m vliw …`.

**Нет цвета в выводе, хотя терминал цветной**
Проверьте, не перенаправлен ли вывод в файл/пайп (`> file`, `| less`) — тогда
цвет автоматически выключается, это ожидаемо. Форсировать: `--color`. И
наоборот, если цвет мешает (например, парсите вывод скриптом) — `--no-color`.

**Tab и стрелки не работают, каждая команда — только руками**
Скорее всего, модуль `readline` недоступен в вашей сборке Python (типично для
некоторых версий на Windows). Сама программа при этом работает нормально,
просто без дополнения и истории. На Linux/macOS `readline` обычно есть из
коробки.

**История не запоминается между запусками**
Проверьте права на запись в домашнюю директорию — история пишется в файл
`~/.vliw_history`. Если файл создать не удаётся, история просто не
сохраняется (это не мешает работе в рамках одной сессии).

**Хочу вывод без рамок/цвета для лога или другого скрипта**
`python3 -m vliw --no-color run slotclash > report.txt` — весь ASCII-арт и
таблицы остаются, просто без управляющих кодов цвета.

**Долгая команда (`/sweep`, `/selfcheck`, `/all` на широких профилях) висит**
Это ожидаемо — точный поиск оракула может занимать секунды на каждый граф.
Понизьте `--budget`/`--seeds`/`--time-limit`, либо дождитесь, либо прервите
Ctrl+C (безопасно, см. выше).
