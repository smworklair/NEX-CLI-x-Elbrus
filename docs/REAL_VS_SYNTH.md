# Real Code vs. Synthetic Benchmarks

> Stage 11 of 13 · [← Machine Model](ISA.md) · [Roadmap](README.md) · [Learned LLM →](LEARNED.md)

The boundary without which the project's numbers are easy to misread: real `lcc` output and the synthetic training set come from different distributions. Locally reproducible via:

```bash
python3 tools/check_real_vs_synth.py
```

## Where the Numbers Come From

Cross-compiler `lcc` 1.29.16 compiles five ordinary C programs (accumulation, floating-point math, branching, memory copy, string hashing) at `-O0/-O2/-O3`. The output is parsed by the same parser used everywhere in the project.

Compiling the same loop with native `lcc` on an `e2k` machine over SSH yielded 49 operations vs. 50 — the cross-compiler is representative, so hardware access is not required for this check.

## Key Finding: The Vocabularies Don't Overlap

The training set covers eight integer classes: `ADD`, `MUL`, `LOAD`, `SUB`, `AND`, `SHL`, `DIV`, `STORE`.

In real compiler output:

- **37% of operations get classified as `UNKNOWN`** — their mnemonics are not in the dictionary.
- These are not exotic instructions: predicates (`cmpesb`, `landp`), packed SIMD (`qpaddw`), AAU (`aaurw`, `fapb`), and all floating-point ops (`faddd`, `fmuld`). On a `double` program, **100%** of ops are unknown.
- Conversely, `DIV` makes up 3–7% of synthetic graphs, yet never appeared once in real output.
- Sizes: synthetic graphs have 4–24 operations, while a one-line `memcpy` at `-O3` produces 112.

## Caveat

`UNKNOWN` is a placeholder: latency 1, any channel. A schedule built over it does not match physical hardware: `fdivd` does not execute in 1 cycle. The point of keeping `UNKNOWN` explicit is so this gap stays **visible in every report** instead of being silently disguised as `ADD`.

Timings will only become accurate once `MNEMONICS` is populated with real classes and measured port constraints. Until then, any result on real code should be read as: **"graph structure — roughly right; timings — no"**.

## What Follows

1. **Narrow the claim** to the integer ALU subset of `e2k` — within that scope, current data is valid.
2. **Expand the dictionary** — predicates, SIMD, AAU, floating point. That is weeks of probing, not hours.
3. **Train on `lcc` output** instead of synthetic graphs. The reference label then becomes the compiler's heuristic rather than a proven optimum.

This is a priority fork, not a technical dependency: training data is generated by `tools/vliw_gen.py` via CP-SAT and does not import the assembly parser.

## What This Means for TINY AI

TINY AI substantially outperforms greedy on hard graphs, but total gain on real code is bounded because greedy is already optimal on 94% of blocks. Detailed figures: [`TINY.md`](TINY.md).
