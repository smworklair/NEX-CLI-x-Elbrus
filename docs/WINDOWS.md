# NEX CLI на Windows

Инструмент писался и в основном гоняется на Linux/macOS, но специально
проверен и работает на Windows — целиком, включая рабочее место. Здесь
только то, что на Windows отличается от остального `docs/CLI.md`: команды
чуть другие, а пара мелких засад ловится один раз и больше не мешает.

## 1. Python

Нужен **Python 3.10 или новее**. Проверить, что уже стоит:

```powershell
py --version
```

Если команда не найдена — поставить с [python.org](https://www.python.org/downloads/)
(отметить галку **Add python.exe to PATH** на первом экране инсталлятора,
иначе следующий шаг не найдёт `python`) или через `winget`:

```powershell
winget install Python.Python.3.12
```

**`python3` на Windows обычно не существует** — команда называется `python`
или `py` (штатный лаунчер, сам находит нужную версию). Везде дальше в этом
файле и в остальной документации, где написано `python3`, на Windows
подставляйте `python` (или `py`).

## 2. Получить код

С `git` (обычный путь):

```powershell
git clone <ссылка-на-репозиторий>
cd vliw-ai-scheduler-demo
```

Без `git` — на странице репозитория **Code → Download ZIP**, распаковать,
открыть терминал в распакованной папке.

## 3. Виртуальное окружение и установка

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[tui]"
```

**Если вторая строка падает с ошибкой про политику выполнения** —
`...cannot be loaded because running scripts is disabled on this system` —
это не поломка проекта, а штатная защита PowerShell от случайного запуска
чужих `.ps1`. Разрешить для текущего окна терминала, не трогая систему
целиком:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

и повторить активацию. В обычном `cmd.exe` (не PowerShell) активация без
`.ps1` вообще: `.venv\Scripts\activate.bat`.

## 4. Запуск

```powershell
python -m vliw run slotclash
python -m vliw               # рабочее место: экран выбора
python -m vliw code          # сразу в КОД
```

Если `.venv` активирован и `pip install -e .` отработал, доступна и короткая
форма — просто `vliw` вместо `python -m vliw`.

## 5. Две вещи, которые на Windows иначе, чем в остальных доках

**Кириллица в `--help` и в остальном выводе.** На части Windows-консолей
кодовая страница по умолчанию не умеет кириллицу, и без починки текст
выглядит квадратами. Инструмент переключает вывод на UTF-8 сам при
запуске — если у вас всё же квадраты, значит версия старее коммита
`25cf183`, обновите репозиторий.

**Tab-дополнение и история команд в построчном режиме.** Обе возможности
идут от модуля Python `readline`, которого в стандартной сборке Python для
Windows нет (см. `docs/CLI.md`, раздел про Tab и историю). На рабочем месте
(том самом, что открывается по `python -m vliw`) это не касается ничего —
там свой ввод, не через `readline`. Не хватает истории по стрелке вверх
может только в построчном пути (`--plain`, пайпы, скрипты) — там текст
просто набирается заново каждый раз, ничего не падает.

## АГЕНТ говорит «нет сети» / «ключ не задан» — это не поломка

Так и задумано: без ключа агент честно отвечает по уже посчитанным
числам, а не выдумывает. Но если хочется живого ответа — вставьте любой
API-ключ. Ничего скачивать не нужно — агент ходит по сети обычным
HTTPS-запросом (`urllib` из стандартной библиотеки, без пакетов).
Формат backend'ов — как в Nex-pilot: один интерфейс, по файлу на
провайдер (`vliw/agent/backends/`), агент не знает, какой API за ним.

Поддерживаются (выбор — `NEX_PROVIDER`):
`mistral` (по умолчанию), `gemini`, `openai`, `deepseek`, `qwen`,
`kimi`, `custom` (любой OpenAI-совместимый: OpenRouter, Ollama, vLLM —
через `NEX_BASE_URL` + `NEX_MODEL`), `gigachat` (Сбер, РФ),
`yandex` (YandexGPT, РФ).

1. Заведите ключ нужного провайдера: [Mistral](https://console.mistral.ai/api-keys),
   [Google AI Studio](https://aistudio.google.com/apikey),
   [GigaChat](https://developers.sber.ru/portal/products/gigachat),
   [Yandex Cloud](https://yandex.cloud/ru/docs/foundation-models/) — или
   поднимите локальную Ollama.
2. Вставь ключ прямо в АГЕНТЕ одной строкой (вступает в силу сразу,
   живёт только до закрытия терминала, **никуда не сохраняется** —
   ни в `.env`, ни в git):

   ```
   /ai deepseek key=sk-ваш-ключ
   ```

   Проще всего вообще без команд: зайди в АГЕНТ — он сам попросит ключ
   до начала работы. Вставил — и спрашивай, провайдер угадается по виду
   ключа. Всё в одном окне, GIT-панели в агенте нет.

   GigaChat — парой OAuth, Yandex — ключ + каталог, свой сервер — адресом:

   ```
   /ai gigachat key=<client_id>:<client_secret>
   /ai yandex folder=... key=...
   /ai custom url=http://localhost:11434/v1 model=qwen2.5:3b key=ollama
   ```

   По частям — тоже можно: `/ai deepseek` (смена) + `/key sk-...`
   (ключ). Всё это — только на сессию: закрыл терминал — настроек нет,
   на диск ничего не пишется. Вручную написанный `.env` (формат — в
   `.env.example`) по-прежнему читается, но сам инструмент туда ничего
   не кладёт. Для скриптов без терминала — переменные окружения
   (`NEX_PROVIDER`, `NEX_API_KEY`, …).
3. Проверьте: `/ai` — должен показать провайдера и что ключ принят.

Секрет строкой в коде не лежит никогда (17.08.2026 два ключа так утекли в
git — отозваны, см. шапку `vliw/agent/llm.py`). Больше того: секрет не
лежит и в файлах вообще — только в памяти текущей сессии.

### Про локальные веса (исторический трек, удалён)

Раньше агент умел отвечать через модель на этой машине (llama-server +
веса в `vendor/`, 2–10 ГБ), а планировщик — через обученный LoRA-адаптер
(`training/checkpoints/`). Замер честный и отрицательный: на настоящем
коде после `lcc` модель не обошла случайный перебор ни на одном графе
(`real_candidates_100_400/model_eval/REPORT.md`), а разговор формулирует
беднее облака. Поэтому веса с диска удалены — в git они и так не лежали
(`vendor/`, `training/checkpoints/*/`, `*.safetensors` в `.gitignore`).
Код трека оставлен и без весов ведёт себя честно: `/learned --status`
говорит «адаптеров не найдено», агент без ключа отвечает офлайн по
посчитанным числам. Вернуть веса (не нужно, но можно):
`tools/setup_local_llm.sh` скачает базу и бинарники заново;
LoRA-адаптеры — на [huggingface.co/Shmonika/nex-vliw-lora](https://huggingface.co/Shmonika/nex-vliw-lora).
Планировщик при этом — крошки из `vliw/tiny/` (21К параметров,
миллисекунды, без LLM).
