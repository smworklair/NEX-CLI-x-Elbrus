# NEX CLI на Windows

Инструмент писался и в основном гоняется на Linux/macOS, но специально
проверен и работает на Windows — целиком, включая рабочее место. Здесь
только то, что на Windows отличается от остального `docs/CLI.md`: команды
чуть другие, а пара мелких засад ловится один раз и больше не мешает.

## 1. Python

Нужен **Python 3.10 или новее**. Проверить, что уже стоит:

```powershell
py --version
```

Если команда не найдена — поставить с [python.org](https://www.python.org/downloads/)
(отметить галку **Add python.exe to PATH** на первом экране инсталлятора,
иначе следующий шаг не найдёт `python`) или через `winget`:

```powershell
winget install Python.Python.3.12
```

**`python3` на Windows обычно не существует** — команда называется `python`
или `py` (штатный лаунчер, сам находит нужную версию). Везде дальше в этом
файле и в остальной документации, где написано `python3`, на Windows
подставляйте `python` (или `py`).

## 2. Получить код

С `git` (обычный путь):

```powershell
git clone <ссылка-на-репозиторий>
cd vliw-ai-scheduler-demo
```

Без `git` — на странице репозитория **Code → Download ZIP**, распаковать,
открыть терминал в распакованной папке.

## 3. Виртуальное окружение и установка

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[tui]"
```

**Если вторая строка падает с ошибкой про политику выполнения** —
`...cannot be loaded because running scripts is disabled on this system` —
это не поломка проекта, а штатная защита PowerShell от случайного запуска
чужих `.ps1`. Разрешить для текущего окна терминала, не трогая систему
целиком:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

и повторить активацию. В обычном `cmd.exe` (не PowerShell) активация без
`.ps1` вообще: `.venv\Scripts\activate.bat`.

## 4. Запуск

```powershell
python -m vliw run slotclash
python -m vliw               # рабочее место: экран выбора
python -m vliw code          # сразу в КОД
```

Если `.venv` активирован и `pip install -e .` отработал, доступна и короткая
форма — просто `vliw` вместо `python -m vliw`.

## 5. Две вещи, которые на Windows иначе, чем в остальных доках

**Кириллица в `--help` и в остальном выводе.** На части Windows-консолей
кодовая страница по умолчанию не умеет кириллицу, и без починки текст
выглядит квадратами. Инструмент переключает вывод на UTF-8 сам при
запуске — если у вас всё же квадраты, значит версия старее коммита
`25cf183`, обновите репозиторий.

**Tab-дополнение и история команд в построчном режиме.** Обе возможности
идут от модуля Python `readline`, которого в стандартной сборке Python для
Windows нет (см. `docs/CLI.md`, раздел про Tab и историю). На рабочем месте
(том самом, что открывается по `python -m vliw`) это не касается ничего —
там свой ввод, не через `readline`. Не хватает истории по стрелке вверх
может только в построчном пути (`--plain`, пайпы, скрипты) — там текст
просто набирается заново каждый раз, ничего не падает.

## АГЕНТ говорит «нет сети» / «ключ не задан» — это не поломка

Так и задумано: без ключа и без локальных весов агент честно отвечает по
уже посчитанным числам, а не выдумывает. Но если хочется живого ответа —
есть два РАЗНЫХ способа, не один, и они не взаимозаменяемы.

### Способ 1 — ключ внешнего провайдера (самый простой на Windows)

Ничего скачивать не нужно — агент просто ходит по сети в Mistral или
Gemini, обычным HTTPS-запросом (`urllib` из стандартной библиотеки, без
дополнительных пакетов). Займёт пять минут:

1. Завести бесплатный ключ — [Mistral (Le Chat)](https://console.mistral.ai/api-keys)
   или [Google AI Studio](https://aistudio.google.com/apikey).
2. Сохранить ключ одним из двух способов:

   ```powershell
   # только для текущего окна PowerShell:
   $env:NEX_API_KEY = "ваш-ключ"

   # навсегда, во всех новых окнах:
   setx NEX_API_KEY "ваш-ключ"
   ```

   или файлом (сработает без переменных окружения вообще):

   ```powershell
   New-Item -ItemType Directory -Force "$env:USERPROFILE\.config\nex" | Out-Null
   "ваш-ключ" | Out-File -Encoding utf8 -NoNewline "$env:USERPROFILE\.config\nex\key"
   ```

3. Проверить: `python -m vliw ai` — должен показать провайдера и что ключ
   принят.

Провайдер определяется по виду ключа автоматически (Mistral по умолчанию,
Gemini — если ключ начинается на `AIza`); переключить руками —
`NEX_PROVIDER=mistral` или `gemini`.

### Способ 2 — свои локальные веса (тяжелее, и на голом Windows не работает)

Это ДРУГАЯ вещь: не облачный чат, а обученный на этом проекте адаптер,
считающий на собственном железе без сети вообще. Веса лежат отдельно —
[huggingface.co/Shmonika/nex-vliw-lora](https://huggingface.co/Shmonika/nex-vliw-lora),
подробности в `docs/LEARNED.md`.

**Важная оговорка, а не мелкий шрифт:** `tools/setup_local_llm.sh` качает
**Linux-бинарник** (`llama-…-bin-ubuntu-x64.tar.gz`) — на голом Windows он
не запустится вообще, это не какая-то настройка, а другой формат
исполняемого файла. Рабочий путь на Windows — через
[WSL](https://learn.microsoft.com/windows/wsl/install) (`wsl --install`,
затем весь `docs/LEARNED.md` целиком выполняется уже ВНУТРИ WSL, как на
обычном Linux). Без WSL этот способ на Windows недоступен — переходите к
способу 1.

Если веса всё же подняты (хоть на Windows через WSL, хоть где угодно ещё) —
**ключ вообще не нужен**: агент сам выбирает локальную модель первой, если
она готова, и только при её отсутствии идёт во внешний провайдер. Это не
запасной путь похуже, а равноправный — просто без сети и без чужой квоты.
